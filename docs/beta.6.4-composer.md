# 0.2.0-beta.6.4 聊天输入栏键盘适配

本轮只处理聊天输入栏上顶，保留 beta.6.3 的历史栏、连接详情和配色，不切换新的页面架构。

## 已确认的原因

beta.6.3 的 iPhone 诊断显示，键盘弹出后 `innerHeight` 和 `visualViewport.height` 都保持 874px，但 Obsidian 的 `--keyboard-height` 变为 328px，宿主内容区从 760px 缩到 432px。同时其安全区变量变为 328px。旧判断没有识别键盘，输入区域继续保留 414px 底部空白，总高度达到 475px，将消息区挤到 0px。

## 修改

`MobileViewportController.update()` 同时读取 Obsidian 已提供的原生键盘状态，触发现有输入栏键盘样式，将其底部留白恢复为 8px。页面仍使用宿主与可见视口的交集，不再次扣除键盘高度，不设置手机键盘高度，不移动或重建输入框。

## 验证

- 在已有视口测试中加入真实数值回归：修复前失败，修复后通过。
- 覆盖窗口高度不变、原生键盘出现、收起后恢复、无输入焦点及原浏览器视口回退行为。
- 253 项 JavaScript 测试及 96 项安装器版本与事务测试通过；两文件修复和版本元数据经过独立审查。
- 完整生产样式的浏览器 A/B 回放通过 16 项检查：旧版复现消息高度 0px；候选版在同样 432px 宿主内保留 315px 消息区，输入框下缘为 533px，宿主下缘为 546px。收起后恢复到原有布局。
- 回放采用真实 390×874 iframe，窗口和 visualViewport 始终为 874px。桌面缺少 iPhone 的环境安全区，因此仅在临时回放样式中映射其 34px 环境值；生产 CSS 未修改。该回放不证明系统软键盘动画已经通过真机验收。
- 真机复测尚未完成；模拟回放和单元测试不能替代真实软键盘验收。

## 本机安装

签名校验后通过完整生命周期入口完成更新与验证，结果为 `installation_ready`、`verification_ready`。已安装插件三文件与签名产物一致；Mac 插件已重载，Bridge 连接、会话绑定与兼容性均正常。手机需重新加载插件后做真实软键盘复测。

配套组件版本统一为 beta.6.4，沿用现有 Tailscale 连接和配对。此候选不更新 VPS，不发布 GitHub Release 或 Obsidian 市场。
